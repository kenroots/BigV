🦁 BigV — System Architecture

How wildlife detection, AI analysis, and community alerts work together

Frontend (Browser/PWA) Backend (FastAPI) AI / YOLOv8 Real-time (WebSocket) Community / Waze
STAGE 1 📱
User Opens BigV App
Browser loads the PWA. Service worker registers for offline support. App requests camera permission, notification permission, and GPS location.
  • PWA installs to home screen (Android/iOS)
  • GPS watchPosition() starts tracking coordinates
  • Notification.requestPermission() called
  • Unique client ID generated (e.g. bigv-a3f9x2)
Frontend
▼
STAGE 2 🔌
WebSocket Connection Established
App opens a persistent WebSocket to /ws/{clientId}. Server registers the client in the Connection Pool. Server sends back recent sightings and total count.
  • wss://your-server/ws/bigv-a3f9x2
  • Server sends "connected" message with last 5 sightings
  • Auto-reconnects every 3s if connection drops
  • All connected users share the same live feed
LIVE WebSocket
Real-time
▼
STAGE 3A 📷
Live Camera Capture
User taps Start. Rear camera activates on mobile. Every 1.5 seconds, a frame is captured from the video feed, scaled to 50% and compressed to JPEG.
  • getUserMedia() — rear cam on mobile
  • Canvas scales frame to 50% for speed
  • JPEG quality 0.7 to reduce bandwidth
  • Frame sent as base64 via WebSocket
Frontend
STAGE 3B 📍
GPS Coordinates Attached
Every frame sent to the server includes the user's current GPS latitude and longitude. This enables Waze-style proximity alerts.
  • navigator.geolocation.watchPosition()
  • lat/lng attached to every WebSocket frame message
  • Also attached to image uploads
  • Shown in header badge when acquired
Community
▼
STAGE 4 ⚙️
Backend Receives & Decodes Frame
FastAPI WebSocket handler receives the JSON message. Base64 image is decoded to a NumPy array using OpenCV. GPS coordinates and location string are extracted.
  • base64.b64decode() → numpy array → cv2.imdecode()
  • Runs in async event loop (non-blocking)
  • Handles errors gracefully — sends error message back to client
Backend
▼
STAGE 5A 🔍
YOLOv8 Detection
WildlifeDetector runs YOLOv8 on the frame in a thread pool (non-blocking). Returns bounding boxes, labels, and confidence scores.
  • yolov8n.pt — 6MB, fast inference
  • 80+ COCO classes + extended wildlife labels
  • Confidence threshold: 0.45 (configurable)
  • Returns: label, confidence, bbox {x1,y1,x2,y2}, priority
AI / YOLOv8
STAGE 5B 🤖
Wildlife Agent Reasoning
WildlifeAgent adds intelligence on top of raw detections. Maintains memory of last 20 detections per camera.
  • Danger score: 0–100% based on animal type × confidence
  • Behavior inference: group / solitary / foraging
  • Natural language summary generated
  • Safety recommendations per species
  • Repeat sighting detection (territory warning)
AI Agent
▼
STAGE 6 📋
Sighting Record Created
If animals are detected, a full sighting record is built and stored in memory. Includes all detection data, GPS coordinates, reporter ID, and AI summary.
  • Unique UUID assigned to each sighting
  • Alert level: critical / high / medium / low (based on confidence)
  • GPS lat/lng stored for map display
  • reporter_id stored to distinguish "your" vs "community" sightings
  • Stored in in-memory list (last 1 hour queryable via /community-sightings)

📱 Each user's app receives and renders
🗺
Map Pin Added
New Leaflet.js pin appears instantly on the Community Map tab. Color = alert level. Popup shows animal, location, time ago.
  • 🔴 Critical — large red pin
  • 🟠 High — orange pin
  • 🟡 Medium — yellow pin
  • 🟢 Low — green pin
  • ⚪ Your own sightings — solid fill
Map
🔔
Waze Nearby Banner
If another user's sighting is within 10km of your GPS location, a sliding banner appears at the top of your screen.
  • Shows animal + distance (e.g. "2.3 km away")
  • Auto-dismisses after 8 seconds
  • Phone vibrates (100ms pattern)
  • Only fires for OTHER users' sightings
Waze-style
📲
Push Notification
Browser push notification fires for all alerts. Works even when app is in background (if PWA installed).
  • Shows animal name + location
  • Confidence percentage shown
  • Tapping opens the app
  • Critical alerts: phone vibrates 3× pattern
Notification
▼
STAGE 9 🃏
Sighting Card Added to Alerts Tab
Every sighting appears as a card in the Alerts & Sightings tab. Cards show the source (your detection vs community report), thumbnail, GPS coords, and time.
  • 📷 You — blue badge for your own detections
  • 👥 Community — purple badge for other users' reports
  • Thumbnail image shown (your detections only)
  • GPS coordinates shown if available
  • Tap card to see full detail + recommendations
Frontend
🌐 REST API — Available to any client
📡
GET /community-sightings
Returns all sightings from the last 60 minutes with GPS coordinates. Lightweight — no images included. Used by the map on page load and every 30s refresh.
  • Filters by timestamp (last 1 hour)
  • Returns: animals, location, lat, lng, alert_level, timestamp
  • Used to populate map on tab open
REST API
❤️
GET /health
Health check endpoint. Returns server status, model name, connected clients, and total sightings. Polled every 15 seconds by the frontend.
  • status, detector model name
  • connected_clients count
  • total_sightings count
  • Used to update stats bar
